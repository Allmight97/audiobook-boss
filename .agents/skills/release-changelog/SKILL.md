# release-changelog

Skill for low-churn release and changelog management in Audiobook Boss.

## When to use

Use this skill when the user asks to:
- cut a release,
- draft/update changelog entries,
- or summarize merged PR activity into a release note section.

## Contract (single source of truth)

- Changelog prose is generated by this skill flow using `scripts/generate-release-changelog.sh`.
- `scripts/release.sh` is a deterministic executor (validate, bump, build, optional commit/tag).
- Do not introduce a second changelog generator in CI for this repo phase.

## Inputs

- Target version (SemVer), e.g. `1.0.1`
- Release date (`YYYY-MM-DD`; default system date if user does not specify)
- Optional base tag override when release scope is not last-tag-to-HEAD

## Workflow

1. Draft release notes from merged PR metadata.
2. Show draft diff/section to user and require explicit approval.
3. Apply changelog update (reset `[Unreleased]`, insert versioned section).
4. Run release executor with explicit flags.

## Commands

Draft only:

```bash
scripts/generate-release-changelog.sh --version 1.0.1 --date 2026-02-22
```

Apply to `CHANGELOG.md`:

```bash
scripts/generate-release-changelog.sh --version 1.0.1 --date 2026-02-22 --apply
```

Run release executor without commit/tag:

```bash
scripts/release.sh --version 1.0.1 --changelog-verified --no-commit-tag
```

Run release executor with commit/tag:

```bash
scripts/release.sh --version 1.0.1 --changelog-verified --commit-tag
```

## Guardrails

- Fail fast if `CHANGELOG.md` does not contain `## [Unreleased]`.
- Fail fast if target release header already exists.
- Fail fast if target release header format is invalid (`## [x.y.z] - YYYY-MM-DD`).
- Never auto-tag without explicit user approval.
- Keep user-facing changelog language concise and outcome-oriented.
