## Architecture Snapshot (Current State)

### Frontend: Vanilla TypeScript + Imperative DOM

**No framework exists.** The UI is hand-written TypeScript with imperative DOM manipulation:

- **Structure**: Single monolithic `index.html` (961 LOC) defines all UI structure as static HTML
- **Logic**: TypeScript modules in `src/ui/` grab elements via `document.getElementById()` / `querySelector()`
- **Wiring**: Each module exports an `init*()` function called from `src/main.ts` on `DOMContentLoaded`
- **State**: Module-level `let` variables + manual DOM sync (`.textContent`, `.classList`, `.style`)
- **Events**: Manual listener attachment in `init*()` functions

**Key implication**: Migration is not "swap out framework X for framework Y" — it's introducing the *first* component framework and converting imperative DOM code to declarative Svelte components.

### Styling: Tailwind v4 + Custom CSS (Hybrid)

**Tailwind v4 is already installed and wired**:
- PostCSS config: `postcss.config.js` uses `@tailwindcss/postcss`
- Tailwind config: `tailwind.config.js` scans `index.html` + `src/**/*.{js,ts}`
- Entry point: `src/styles.css` starts with `@import "tailwindcss";`

**Current usage**:
- ~1,600 lines of hand-written CSS in `src/styles.css` using CSS custom properties for theming (`--bg-main`, `--text-primary`, etc.)
- Tailwind utilities used sparingly in `index.html` (`flex`, `gap-2`, `text-xs`, `mb-2`) alongside custom classes
- Some hand-rolled utility classes duplicate Tailwind (`.grid-cols-2`, `.text-xs`)

**Key implication**: "Add Tailwind" is *not* Phase 1 work — Tailwind is ready. Phase 1 is really "Add Svelte to Vite + design token system."

### IPC Layer: Three-Tier Typed Bridge

**Tier 1 — Generated bindings** (`src/lib/generated/tauri.ts`, 473 LOC):
- Auto-generated by tauri-specta via `bun run bindings:generate`
- 17 commands, 2 events, all Rust types exported as TS
- **Never hand-edited** (drift check in `scripts/checks.sh standard`)

**Tier 2 — Bridge adapter** (`src/lib/bridge.ts`, 363 LOC):
- Wraps generated bindings with legacy snake_case command names (`"analyze_audio_files"`, `"save_metadata_to_file"`)
- Normalizes between Generated types (uses `null`) and Legacy types (uses `undefined`)
- Provides `bridge.invoke()`, `bridge.listen()`, `bridge.open()`, `bridge.openExternal()`
- Falls back to mocks in dev when Tauri unavailable
- **Tracked as FALLBACK[FB-008]** — sunset 2026-05-31, issue #203

**Tier 3 — UI callsites**: Components call `bridge.invoke("command_name", { args })`

**Key implication**: Bridge layer is framework-agnostic. Svelte components import and call `bridge.*` directly — no additional adapters needed. Bridge stays until FB-008 is retired.

### Build Tooling

- **Vite**: Minimal config (`vite.config.ts`), no framework plugins yet
- **TypeScript**: Strict mode, ES2020 target, bundler resolution
- **PostCSS**: Only `@tailwindcss/postcss`
- **Tailwind**: Content scan includes `index.html` + `src/**/*.{js,ts}` — will need `*.svelte` added

## TypeScript Return Type Audit Summary

**Audit date**: 2026-02-10 (agent a9c068b)
**Scope**: All TS files in `src/` (68 files, excludes generated code)

| Category | Found | Unnecessary | Necessary |
|----------|-------|-------------|-----------|
| Explicit function return types | ~270 | ~170-200 | ~70-100 (exports, type guards) |
| Type assertions (`as`) | ~165 | ~10-15 | ~150 (DOM casts, boundary code) |
| Redundant `let` annotations | ~35 | ~15-20 | ~15-20 (`\| null` unions) |
| **TOTAL** | ~470 | **~195-235** | ~235-270 |

**The debate**: Explicit return types on internal/private functions create maintenance burden without safety gain — TS inference already catches drift at callsites. Explicit returns have value at *exported API boundaries* (prevent accidental contract changes) and are *required* for type guards (`is` predicates).

**New convention** (being added to `src/AGENTS.md`):
> "Prefer inference for return types. Explicit return types are encouraged at exported API boundaries and required for type guards (`is` predicates). Omit elsewhere."

**Cleanup scope**:
- Priority 1: Remove `: void` on ~80 private functions (~10-15 files) — mechanical, low-risk
- Priority 2: Remove trivial returns on private fns (~40)
- Priority 3: Remove redundant `let` annotations (~15-20)
- Priority 4: Replace `as HTMLElement` with `instanceof` (~10-15)

**Action**: Standalone GH issue created (not under #206 — repo-wide concern, not migration-specific). Tag `tech-debt`, `frontend`. No milestone.
