## Original Plan (For Reference)

### Current State (Assessment)
- `src-tauri/src/audio/progress.rs` currently combines three concerns:
  - Progress event emission and helpers: `ProgressEmitter`, `ProgressEvent`, `calculate_stage_progress`, `format_eta`, `converting_percentage_from_seconds`.
  - Book-keeping reporter: `ProgressReporter` and its methods.
  - FFmpeg parsing utilities: `parse_ffmpeg_progress`, `parse_ffmpeg_time`, and `FFmpegProgressState` (currently unused, `#[allow(dead_code)]`).

Key usages to preserve (back-compat via re-exports from `progress/mod.rs`):
- `progress_monitor.rs`: `ProgressEmitter`, `parse_ffmpeg_progress`
- `media_pipeline.rs`: `ProgressEmitter`, `converting_percentage_from_seconds`
- `processor/{finalize,mod}.rs`: `ProgressReporter`, `ProgressEmitter`
- tests: `converting_percentage_from_seconds`

### Finalized Decisions (Implemented)
- Create `src-tauri/src/audio/progress/` with:
  - `mod.rs`: submodule wiring + public re-exports to preserve `crate::audio::progress::*` API.
  - `reporter.rs`: `ProgressEmitter`, `ProgressEvent`, `ProgressReporter`, `calculate_stage_progress`, `format_eta`, `converting_percentage_from_seconds`.
  - `parser.rs`: `parse_ffmpeg_progress`, private `parse_ffmpeg_time`, and `FFmpegProgressState` (kept; may remain `#[allow(dead_code)]`).
- Keep `pub mod progress;` in `audio/mod.rs`. Remove `audio/progress.rs` at the end.
- Preserve all existing import paths for external users/tests via re-exports in `progress/mod.rs`.
- Avoid functional changes; only pure moves and visibility adjustments where required.
