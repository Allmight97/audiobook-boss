## Combined Plan: P1.1.4–P1.1.6 (Cleanup split, Commands split, UI splits)

### Goal
Reduce file/module size and improve maintainability while preserving public APIs and user-visible behavior. This plan combines:
- P1.1.4: Split `audio/cleanup.rs` → `audio/cleanup/{guard.rs, ops.rs, mod.rs}`
- P1.1.5: Split `commands/mod.rs` → `commands/{audio.rs, metadata.rs, system.rs}`
- P1.1.6: Split `ui/fileList.ts` and `ui/statusPanel.ts` into folders with aggregator facades

### Non-Goals
- No functional changes, no renames of commands or public exports, and no event contract changes.
- No legacy removal or behavior changes (those come later in P2 tasks).

### Preconditions Prior to starting each stage
- Pre-work check of codebase and verify current branch state (currently on `feat/p1.1.4_split_cleanup.rs`)
- Baseline green: `cargo test`, `cargo clippy -- -D warnings`, `cargo test --features safe-ffmpeg`, `cargo clippy --features safe-ffmpeg -- -D warnings`, and `npm run build`.
- Establish baseline size snapshot (current: cleanup.rs=503 LOC, commands/mod.rs=280 LOC, fileList.ts=537 LOC, statusPanel.ts=443 LOC):
```bash
bash scripts/sg/size_budget.sh
```

### Invariants (must not break)
- Tauri command names used by TS via `invoke(...)` are unchanged (same function names and `#[tauri::command]`).
- `lib.rs` `tauri::generate_handler!` list remains unchanged.
- TS imports stay stable: `./ui/fileList`, `./ui/statusPanel`, and their exported symbols (`displayFileList`, `toggleFileSort`, `clearAllFiles`, `currentFileList`, `initStatusPanel`, `getStatusPanel`).
- Event contract in `src/types/events.ts` remains valid (`'processing-progress'`).
