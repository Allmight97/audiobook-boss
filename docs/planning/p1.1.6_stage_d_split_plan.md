## P1.1.6 – Stage D Split Plan: `statusPanel'

### Goal
Split `src/ui/statusPanel.ts` into a small aggregator shim plus `statusPanel/` submodules while preserving behavior and public imports. Aim for an overall ≥4/5 rating on completeness, clarity, and type safety with minimal phases.

### Invariants
- Keep imports stable: `import { initStatusPanel, getStatusPanel } from "./ui/statusPanel"` must continue to work.
- Public surface unchanged: `StatusPanel`, `initStatusPanel()`, `getStatusPanel()`.
- No functional changes, no event contract changes. Continue to listen to `'processing-progress'` and use existing invoke calls.
- TypeScript strict mode must pass; avoid introducing `any`.

---

## Phase 1 — Create structure and move view helpers (P0)

Purpose: Establish new folder, extract DOM/view helpers to keep logic lean.

Tasks (atomized)
1) Create folder and files
   - `src/ui/statusPanel/`
     - `dom.ts`: element lookup, UI updates (progress bar, texts, button state, art thumbnail display/reset), and small helpers.
     - `logic.ts`: core behavior and state; imports helpers from `dom.ts`.
     - `index.ts`: re-export public API: `StatusPanel`, `initStatusPanel`, `getStatusPanel`.

2) Extract DOM responsibilities into `dom.ts`
   - Move element caching/lookup (`getElementById` and query selectors).
   - Move UI update helpers: update progress bar, percentage text, status text, step text, process button state.
   - Add `displayCoverArt(dataUrl: string)` and `resetArtThumbnail()`; keep art conversion in logic.

3) Aggregator shim
   - Replace contents of `src/ui/statusPanel.ts` with re-export: `export * from './statusPanel/index';`.

Acceptance criteria
- TypeScript builds with the new files present (temp wire-up allowed during Phase 1).

## Phase 2 — Move logic and wire events (P0)

Purpose: Move class logic with minimal changes, wire to `dom.ts` helpers, preserve exact behavior and API.

Tasks (atomized)
1) Move class and public API
   - Move `StatusPanel` class to `logic.ts` with the same constructor signatures and public getters.
   - Keep `initStatusPanel` singleton pattern and `getStatusPanel` in `logic.ts` and export via `index.ts`.

2) Wire event listeners
   - Keep `listen('processing-progress', ...)` behavior identical.
   - Keep `invoke('process_audiobook_files')` and `invoke('cancel_processing')` flows.
   - Move DOM element access to `dom.ts` APIs; no direct `document.getElementById` in `logic.ts` aside from initial bootstrap if needed.

3) Cover art logic
   - Keep `convertBytesToDataUrl` in `logic.ts`.
   - Use `dom.ts` to display or reset art thumbnail.

Acceptance criteria
- `npm run build` succeeds.
- Manual smoke under `npm run tauri dev` shows unchanged behavior for start/cancel, progress updates, and art thumbnail display.
