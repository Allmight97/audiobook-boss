# Audit Remediation Plan

## Goals

- Prevent unexpected panics in the audio buffer when FFmpeg reports new sample formats.
- Reintroduce guaranteed `.m4b` validation for output paths so callers cannot forget the check.
- Capture the agreed approach in `docs/planning/audit-remediation-plan.md` for future reference.

## Tasks

1. **sample-accumulator-guard**  

- Update [`src-tauri/src/audio/buffer.rs`](src-tauri/src/audio/buffer.rs) so `SampleAccumulator::new` returns `Result<Self, AppError>` rather than panicking on unsupported formats.  
- Explicitly handle both known AAC formats (`F32` planar, `I16` packed) plus any additional FFmpeg sample types the pipeline could surface (e.g., `F32` packed, `I16` planar) by converting them into a supported storage representation.  
- Add unit tests covering each newly supported format plus the error path to ensure we fail fast with an actionable message instead of bringing down the process.  
- Run `cargo test -p audiobook-boss --audio::buffer` (or full `scripts/quick-checks.sh`) to confirm regressions are avoided.

2. **output-path-validation**  

- Strengthen [`prepare_output_path` in src-tauri/src/commands/audio.rs](src-tauri/src/commands/audio.rs) so the helper always enforces `.m4b` extension validation (or returns a typed error) before creating directories.  
- Ensure all callers still run `validate_audio_settings` but are no longer able to bypass the extension guard inadvertently.  
- Extend integration tests in `src-tauri/tests/path_validation_integration.rs` to cover invalid extensions submitted via v2 payloads.  
- Rerun `cargo test path_validation` plus `scripts/quick-checks.sh` to verify coverage.

3. **planning-doc**  

- Write the finalized remediation approach and checkpoints into `docs/planning/audit-remediation-plan.md` so future sessions can track progress.  
- Outline success criteria, owner, and links to relevant PRs in the document.

## Verification

- `scripts/quick-checks.sh` (fmt, clippy, contract check, TS type check) must pass.
- `npm run test` to ensure Vitest remains healthy after any TypeScript touchpoints.
- Manual sanity test: run `ABB_DISABLE_FASTPATH=1 npm run tauri dev`, trigger a processing run, and confirm neither the accumulator nor output-path logic produces new warnings.

*A copy of this plan will be saved to `docs/planning/audit-remediation-plan.md` once approved.*
