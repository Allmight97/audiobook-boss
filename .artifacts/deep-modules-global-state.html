Frontend / Backend Mental Model

split by runtime, owned by product module

The frontend/backend split stays real as a runtime boundary. It stops being the main architecture map. The new map is product modules with frontend and backend edges.

Old question

Is this frontend code or backend code?

Better question

Which product decision owns this rule?

Practical result

Frontend code renders or submits module truth; backend code decides durable artifact, metadata, and execution truth.

Processing Plan mostly backend module
Frontend edge

Submits user intent through tauriClient.processAudiobookFiles and displays the preflight result.

Backend owner

Builds the resolved processing plan: safe inputs, metadata projection, output requests, collision state, and review signature.

Output Artifact cross-runtime module
Frontend edge

Renders backend output plans, collects review decisions, and sends reviewed signatures back.

Backend owner

Owns requested path, resolved path, source overlap rules, collision policy, parent dirs, and final commit action.

Metadata Intent shared semantic contract
Frontend edge

Captures user intent as set, clear, or noop; compiles wire patch ops at the Tauri boundary.

Backend owner

Applies intent into processing overlays, naming metadata, save metadata, write plans, and cover-art passthrough behavior.

Tauri Runtime frontend-owned boundary
Frontend owner

tauriClient is the public API. It hides generated bindings, nullish conversion, event names, and app-error normalization.

Backend edge

Rust commands and generated bindings are the contract source, but UI code should not import generated runtime details directly.

Status Runtime mostly frontend module
Frontend owner

Owns status state, event reduction, feedback text, view-state derivation, and terminal outcome display.

Backend edge

Backend emits progress, queue, cancellation, failure, and terminal result events. Status runtime turns those into user-visible truth.

How Much Code Actually Changes?

Processing Plan: medium

Some code moves now. Most logic stays the same but gets re-owned behind a planner API.

Output Artifact: high

The largest reshaping: backend path/collision/finalize rules and frontend review flow become one artifact-truth module.

Metadata Intent: medium-high

Less raw code rewrite than semantic consolidation: intent projections and tests move behind one contract.

Tauri Runtime: low-medium

Mostly keep the existing pattern. Split private internals if needed; keep tauriClient stable.

Status Runtime: low-medium

Already close. Tighten exports and tests around visible status behavior.

Tests: high-value churn

Delete or rewrite tests that protect helper layout; add boundary tests that protect module behavior.

One-Screen Takeaway

Old mental load

Understand behavior by tracing arrows between files and remembering which helper owns which rule.

New mental load

Pick the grey-box module, read its API, then inspect internals only when needed.

AI delegation change

Give agents module-internal work with boundary tests. You review interface shape, language, and product truth.
