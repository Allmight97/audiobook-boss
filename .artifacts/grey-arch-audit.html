audio/processor ~3,864 LOC · 12 files

Deepest module

The audio processing pipeline. This is the most complex deep module in the codebase. It hides the full lifecycle of audiobook creation: validation → execution → finalization. The public API is intentionally tiny compared to the internal machinery.

Public API surface:
process_audiobook_with_context(ProcessingContext, Vec<AudioFile>, Option<AudiobookMetadata>, bool) -> Result<String>
detect_input_sample_rate(&Path) -> Result<u32>
resolve_processor_adapter(...) -> ResolvedProcessorAdapter
FfmpegNextProcessor (struct implementing MediaProcessor)

Cluster — Stage Orchestration

prepare.rs execute.rs finalize.rs staging.rs plan.rs

prepare validates inputs, detects sample rates, sets up temp workspace.
execute runs the actual FFmpeg merge/encode (native or external FDK adapter).
finalize writes metadata, moves temp to destination, cleans up.
staging manages destination-adjacent temp directories.
plan defines the MediaProcessingPlan trait and processor selection.

Cluster — Engine & Adapter

engine.rs adapter.rs external_fdk.rs frame_pipeline.rs streams.rs selection.rs preview_state.rs

engine.rs is the in-process ffmpeg-next orchestrator.
adapter.rs resolves whether to use native AAC, Apple AAC (AudioToolbox), or external FDK HE-AAC.
external_fdk.rs shells out to a user-provided FFmpeg binary with libfdk_aac.
frame_pipeline.rs handles preview/full-run frame accumulation and chapter slicing.
streams.rs manages stream setup and codec context.

Cluster — Encoder Subsystem

encoder/mod.rs encoder/write.rs encoder/context.rs encoder/common.rs encoder/options/mod.rs encoder/options/native.rs encoder/options/fdk.rs encoder/options/apple.rs

Encoder options are split by toolchain target. native.rs configures in-process AAC, apple.rs configures AudioToolbox, fdk.rs configures libfdk_aac. write.rs handles the actual packet/frame write loop.

Downstream contracts:
• Emits ProgressEvent / QueueEvent through Tauri window emitter.
• Reads CancellationChecker from job_registry at stage boundaries.
• Calls metadata::save_metadata_with_plan during finalize.
• Calls output_path planning to derive destination paths.

metadata ~2,269 LOC · 12 files

Deep module

The metadata boundary. Owns read/write behavior for audiobook tags across MP4-family (M4B/M4A) and generic containers. Chooses between mp4ameta (direct atom editing) and FFmpeg remux based on actual container classification, not filename suffix.

Public API surface:
read_metadata(path) -> Result<AudiobookMetadata>
save_metadata_with_plan(path, &MetadataWritePlan) -> Result<()>
set_container_metadata(...), validate_metadata_compatibility(...)
MetadataIntentPatch → MetadataWritePlan conversion (intent compilation)
Re-exports: CoverFormat, cover-art stream helpers

Cluster — Read / Write Engine

reader.rs container.rs remux.rs mp4ameta_bridge.rs ffmpeg_dict.rs tag_registry.rs

reader.rs probes and reads tags. container.rs classifies MP4 vs other.
mp4ameta_bridge.rs writes atoms directly for MP4-family files.
remux.rs rewrites metadata via FFmpeg for non-MP4 containers.
ffmpeg_dict.rs builds FFmpeg metadata dictionaries.
tag_registry.rs maps canonical/mirrored tags (Plex/ABS interop).

Cluster — Intent & Cover Art

intent.rs intent_plan.rs passthrough.rs cover_art/mod.rs cover_art/format.rs cover_art/embedding.rs ffi.rs

intent.rs defines patch ops (Set / Clear / Noop) and the MetadataIntentPatch struct.
intent_plan.rs compiles intent into a deterministic MetadataWritePlan.
passthrough.rs preserves chapters and cover art from source files.
cover_art/ handles format detection and embedding as a secondary video stream.

Downstream contracts:
• Consumed by commands::metadata (Tauri commands for read/write).
• Consumed by audio::processor::finalize (post-encode metadata injection).
• Types (AudiobookMetadata, MetadataIntentPatch) are specta-typed and cross the TS↔Rust boundary.

audio/output_path ~1,971 LOC · 7 files

Deep module

Output path planning, naming, collision detection, and filesystem commit. Hides the complexity of template-based naming, collision suffixing, and safe temp→final moves.

Public API surface:
build_output_path_preview(...) -> Result<PathBuf>
derive_output_artifact_path(&Path, OutputKind) -> Result<PathBuf>
enforce_output_plan_review(...) -> Result<()>
OutputPlanReview, ResolvedOutputPlan, CollisionPolicy

Cluster

naming.rs plan.rs review.rs collision.rs artifact.rs commit.rs types.rs

naming.rs builds filenames from metadata templates (title, artist, series, year).
plan.rs resolves the full output plan including directories and extension.
review.rs presents the plan for UI confirmation (collision dialog).

Downstream contracts:

Deep module

The most complex frontend module. Manages job lifecycle state, progress aggregation, queue rendering, and the connection to Tauri events. Uses a local state machine to model UI state transitions independently of Rust event shapes.

Public API surface:

lib/tauri ~783 LOC · 4 files

Boundary adapter

The IPC boundary adapter. Every Tauri command and event crosses through here. Wraps auto-generated specta bindings with normalization, type-safe command specs, and event adapters.

Public API surface:
tauriClient — single object exposing all commands and listen.
commandSpecs — typed command wrappers around generated bindings.

Cluster

client.ts commands.ts normalizers.ts appError.ts

client.ts is the canonical entrypoint; UI code must not call generated bindings directly.

Upstream contracts:

6. Additional High-Level Observations

6.1 Dependency Categories (per deep module)

ModuleDependency categoryNotes
audio/processor Local-substitutable + True external ffmpeg-next is a true external (system FFmpeg libs). The external_fdk adapter shells out to a user-provided binary, making it a port-and-adapter boundary (port = MediaProcessor, adapters = native/FDK/Apple).
metadata Local-substitutable + True external mp4ameta is an external crate (direct atom editing). FFmpeg remux is external tool invocation. The module hides the choice behind save_metadata_with_plan.
audio/job_registry In-process Pure tokio concurrency; no I/O. Deepenable and already deep.
audio/output_path Local-substitutable Filesystem I/O only; could be tested with a temp dir stand-in.
commands Boundary glue Thin layer; not a candidate for deepening. Keeps Tauri wiring separate from domain logic.

6.2 False Seams & Boundary Glue Assessment

Based on the reference criteria (trivial wrappers, identity adapters, dead exports, mirror APIs):

ObservationClassificationRationale
commands::audio_processing::run (761 LOC) Keep Large but owns explicit dispatch logic (merge vs batch), terminal outcome classification, and event emission. Removing it would push orchestration into processor, blurring command/domain boundaries.
commands::audio_processing::plan (707 LOC) Keep Owns collision review, output directory validation, and per-job metadata resolution. This is policy wiring, not pure forwarding.
audio/mod.rs re-exports (~30 re-exports) Keep Semantic umbrella module. The re-exports give callers a single import surface. Removing them would scatter imports across 10+ submodules.
lib.rs metadata re-exports (ffmpeg_add_cover_art_stream_pre_header, etc.) Bundle later Test-facing passthrough helpers. They are legitimate but create a second public surface. Could be consolidated into a test-only facade when the test boundary is next refactored.
frontend ui/core/actions.ts Keep Centralizes metadata-save action orchestration. Thin but expresses domain intent (Cmd+S workflow).

6.3 Notable Architectural Strengths

  • Explicit stage boundaries in processor (prepare → execute → finalize) make the pipeline traceable.
  • Container-aware metadata routing (MP4-family vs remux) is hidden behind a single function.
  • Intent-based metadata edits (Set/Clear/Noop + Recompute) make UI→backend semantics lossless.
  • Generated IPC bindings with drift checks prevent TS↔Rust contract skew.
  • JobRegistry centralizes concurrency, making cancellation and backpressure observable.
  • AGENTS.md files at module boundaries document invariants locally — a strong ownership signal.

6.4 Friction Points (Canary Triggers)

  • Processor size: audio/processor and its encoder subtree exceed the 400 LOC module target. The encoder options split (native/fdk/apple) is good, but the parent module is still a large gravity well.
  • Run orchestrator size: commands/audio_processing/run.rs at 761 LOC is an orchestrator that may accumulate more dispatch logic over time. Worth monitoring for helper extraction.
  • Frontend statusPanel depth: At ~1,699 LOC (plus extensive tests), this is the deepest frontend module. The state machine abstraction is strong, but the render/processing paths could split further.
  • Test-only exports in lib.rs: The ffmpeg cover-art re-exports are public for integration tests. This is a real seam but leaks internal metadata symbols into the crate root.

7. Repo Organization Findings & Proposal

7.1 Current Structure Friction

ObservationImpactExample

Flat test dumping grounds Tests drift from the modules they cover Integration tests live in src-tauri/tests/ without mirroring module structure

7.2 Proposed Target Structure

Align folders with the grey-box / deep-module philosophy: each folder is a product module with a small public surface. Boundary code (commands, IPC, adapters) is extracted into its own layer so domain logic does not leak.

Frontend

src/ui/ → src/modules/ (product-first modules)
src/lib/tauri/ → src/boundary/tauri/ (separate boundary from domain)
Co-locate tests in __tests__/ per module
Add index.ts public API files at every module root

Backend

src-tauri/src/audio/ + commands/ → product modules:
  processing/ — encode, merge, pipeline
  artifact/ — output path, naming, collision, commit
  metadata/ — read, write, intent, cover art
  lifecycle/ — job registry, concurrency, cancellation
Extract boundary/ for commands + ipc_contract.rs + errors.rs
Shrink lib.rs to declarations; move logic into modules

Root Cleanup

Move stray test files (test_compilation.rs, test_quick.rs, test_ui.rs) into scripts/scratch/ or a dedicated experiments/ directory.

7.3 Migration Strategy (4 Phases)

PhaseScopeGoal
1. Boundary extraction commands/, ipc_contract.rs, errors.rs Create src-tauri/src/boundary/ and move Tauri glue there without touching domain logic
2. Domain re-bucketing audio/ → processing/ + artifact/ + lifecycle/ Move files into product modules; keep git history with git mv
3. Frontend alignment src/ui/ → src/modules/; src/lib/tauri/ → src/boundary/tauri/ Same product-first move; update all import paths
4. Public API + tests Add index.ts / mod.rs surfaces; co-locate tests Shrink import paths; enforce that cross-module imports go through the public API

7.4 Open Questions

  1. Module merging scope: Should metadata and cover_art stay separate, or merge into a single metadata/ deep module with internal sub-folders?
  2. Test migration depth: Should integration tests mirror the new module structure, or remain in a single tests/ directory with module-named sub-folders?
  3. Aggressiveness level: Do a one-shot big-bang refactor, or phase it incrementally (one module per PR) to keep reviews reviewable and bisectable?
  4. Workspace split consideration: Should the backend become a Cargo workspace with separate crates (processing, metadata, artifact) to enforce API boundaries at compile time?
  5. Frontend module granularity: Is src/modules/ the right level, or should top-level islands live directly under src/ (e.g. src/statusPanel/)?
